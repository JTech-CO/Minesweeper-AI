# M6-R4 Expert posterior/constraint 정책 설계 제안

**갱신일**: 2026-07-15
**상태**: PROPOSED - 대규모 아키텍처 변경 승인 대기

## 목표와 경계

M6의 기존 0.85/0.60/0.40 승률 게이트를 낮추지 않고 Expert policy-only
수렴을 해결한다. solver는 teacher label 생성에만 사용하며 모델 추론 경로에는
호출하거나 입력하지 않는다. Python과 TypeScript 인코딩 계약, M2 false-positive-0,
고정 validation/test seed를 유지한다.

## 현재 구조의 실패 원인

1. ConstraintGraphBlock은 hidden/clue 이웃 embedding을 평균내므로 clue의 정확한
   잔여 지뢰 수와 미지 셀 cardinality를 보존하지 못한다.
2. risk head 하나에 solver posterior와 실제 mine label의 BCE를 동시에 적용해
   확률 보정과 지뢰 분류 목적이 충돌한다.
3. policy head는 posterior head와 구조적으로 연결되지 않아 risk 학습이 실제 행동
   순위를 바꾸지 못했다.
4. PPO에는 이전 난이도 rehearsal이 없었고, 이를 추가했지만 이미 손상된 표현만으로
   Expert 40%를 만들 수 있다는 증거는 없다.
5. 전체 safe cell 균등 target은 논리적으로 유용한 다음 수의 순위를 제거해 즉시
   붕괴하므로 다시 사용하지 않는다.

## 제안 아키텍처: constraint-posterior-v5

### Count-aware factor graph

- visible clue node와 hidden cell node의 2종 factor graph를 유지한다.
- clue node 입력에 clue value, adjacent hidden count, known-mine count,
  residual mine count를 별도 embedding으로 제공한다.
- hidden-to-clue는 masked sum과 max를 함께 사용해 cardinality를 보존한다.
- clue-to-hidden 메시지는 residual count embedding과 결합한다.
- shared recurrent block 8회로 16x30 전체에 전달하되 valid mask를 매 회 적용한다.
- 구현은 Conv2d, elementwise, reduction만 사용해 M7 ONNX export를 막지 않는다.

### 분리된 출력 head

- posterior head: visible state에서 각 legal cell의 mine posterior를 예측한다.
- mine auxiliary head: 실제 mine layout을 학습 시에만 분류하며 posterior와 분리한다.
- certainty head: unknown, certain-safe, certain-mine 3분류를 유지한다.
- policy head: trunk preference와 예측 posterior를 결합해 안전도와 행동 우선순위가
  실제 추론 점수에 직접 반영되게 한다.
- value head는 현재 masked PPO 계약을 유지한다.

## Teacher distillation

- target은 visible-state solver가 산출한 certain-safe/mine, CSP probability,
  추천 policy만 사용한다.
- 실제 mine layout은 분리된 mine auxiliary head에만 사용한다.
- Expert hard/guess/frontier-component 표본을 우선하고 Beginner와 Intermediate는
  rehearsal 비율로 유지한다.
- 데이터셋은 실행 중 메모리에만 생성하며 checkpoint 외 대용량 파일을 남기지 않는다.
- loss는 policy CE, posterior Brier+NLL, certainty CE, mine BCE, value MSE를
  각각 기록해 한 head의 개선이 다른 목적을 가리지 못하게 한다.

## PPO 보존 장치

- M6에서 구현한 25% previous-difficulty rehearsal을 유지한다.
- teacher checkpoint를 frozen anchor로 두고 current policy와의 masked KL을 적용한다.
- KL coefficient는 고정 smoke suite가 아니라 train trajectory에서만 최적화한다.
- checkpoint 선택은 기존 validation suite로만 하고 test suite는 마지막 한 번 사용한다.
- routine checkpoint는 bootstrap.pt, last.pt, best.pt 세 경로만 덮어쓴다.

## 구현 단위와 게이트

### R4-0 계약 테스트

- 동일 visible board에서 mine layout만 바꿔도 model input과 policy output이 같아야 한다.
- model inference 중 trainer.solver 호출을 monkeypatch로 금지한다.
- 9x9, 16x16, 16x30 padding 전후 valid 영역 output이 허용 오차 내 일치해야 한다.
- 모든 output은 finite이며 illegal/padded action은 선택되지 않아야 한다.
- 기존 M2 false-positive-0과 TS/Python env parity 테스트를 그대로 통과해야 한다.

### R4-1 teacher checkpoint

- 기존 canonical seed와 game 수를 변경하지 않는다.
- Beginner 1,000게임과 Intermediate 200게임은 기존 게이트 이상을 유지한다.
- Expert 500게임은 기존 R2-B 13.6%를 통계적으로 상회해야 PPO에 진입한다.
- posterior Brier/NLL과 certain-safe precision을 기존 risk head 기준선과 함께 기록한다.
- checkpoint 재로드 후 policy, posterior, certainty, value가 bit-identical이어야 한다.

### R4-2 curriculum PPO

- Beginner 최근 500게임 85% 이상 3회 연속.
- Intermediate 최근 500게임 60% 이상 3회 연속.
- Expert 최근 500게임 40% 이상 3회 연속.
- loss NaN/발산 없음과 이전 난이도 rehearsal 비율을 metrics에 기록한다.
- 완료 checkpoint를 독립 validation으로 재평가하고 한 번만 M5 저장소에 발행한다.

## 저장공간과 실패 처리

- 새 production run은 storage/runs/m6-r4 하나만 사용한다.
- teacher sample과 ablation 결과는 메모리 또는 작은 JSONL만 사용한다.
- 실패 checkpoint는 보존하지 않고 manifest와 측정 결과만 문서에 남긴다.
- 서로 다른 방법 3회 실패 시 다시 STOP하며 게이트를 낮추거나 solver hybrid로
  완료를 위장하지 않는다.

## 승인 범위

승인 시 constraint-posterior-v5 모델, 분리 head loss, KL anchor, 관련 테스트와
새 M6-R4 production run까지 구현한다. M7 이후는 M6 40% 게이트 통과 전에는
시작하지 않는다.
