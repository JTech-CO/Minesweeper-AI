# M6-R5 constraint-ranker-v6 설계

**갱신일**: 2026-07-16
**상태**: BLOCKED / STOP - 유효한 R5 방법이 Expert 진입 게이트에 실패

## 문제 정의

M6-R4 constraint-posterior-v5는 고정 canonical 평가에서 Beginner 94.4%,
Intermediate 72.5%, Expert 27.4%를 기록했다. posterior Brier는 0.002723으로
낮았지만, 실제 정책 점수는 preference - posterior penalty만 사용하고 별도로
학습한 certainty head를 사용하지 않았다. 평균 셀 오차가 작아도 Expert 한 판에서
top-1 위험 셀을 한 번 선택하면 즉시 패배하므로 셀 평균 손실과 게임 승률 사이에
구조적 불일치가 있었다.

동일 v5 checkpoint를 변경 없이 분석한 결과는 다음과 같다.

- 기존 policy Expert smoke: 9/32 = 28.125%.
- certainty-only Expert smoke: 12/32 = 37.5%.
- certainty-only Expert validation 200판: 55/200 = 27.5%.
- posterior-only Expert smoke: 5/32 = 15.625%.
- certainty 4.0 + posterior 1.0 + bounded preference: 7/32 = 21.875%.

32판 certainty 결과만으로 40% 달성을 주장할 수 없으며, 단순 head 가중치 변경도
해결책이 아니다. R5는 정책이 실제로 선택하는 상위 셀의 순위 오류를 직접
최적화한다.

## 아키텍처

새 architecture id는 constraint-ranker-v6이다.

1. v5의 visible-only count-aware factor graph, residual trunk, posterior/mine/
   certainty/value heads를 그대로 전이한다.
2. certainty 예측 클래스를 safe > unknown > mine의 엄격한 1차 순위로 사용한다.
3. forward는 hard class를 사용하고 backward는 soft certainty gradient를 사용하는
   straight-through estimator로 certainty head를 학습한다.
4. calibrated posterior mine risk는 같은 certainty class 안의 2차 순위다.
5. 기존 preference는 tanh와 0.25 이하의 상한으로 제한하며 기본값은 0이다.
6. legal mask는 최종 점수에 적용하고 padded/illegal 셀은 선택할 수 없다.

초기값은 certainty weight 4.0, posterior weight 1.0, preference limit 0.0이다.
생성자 검증과 forward scale guard가 posterior 최대 영향과 preference 양방향
상한의 합을 certainty class 간격보다 작게 유지하므로 optimizer가 scale을 바꾼
뒤에도 risk나 preference가 class 우선순위를 뒤집을 수 없다.

모델 입력은 기존 encode_v3의 플레이어 가시 정보뿐이다. solver 호출, solver
출력, 실제 mine layout은 inference 입력에 포함하지 않는다. 구현 연산은 Conv2d,
softmax, sigmoid, tanh, elementwise 연산과 legal masking으로 제한해 M7 ONNX
경로를 막지 않는다.

## 학습 목표

기존 평균 손실은 유지하되 다음 행동 중심 손실을 추가한다.

- policy CE: solver가 허용한 최저 위험 셀 집합에 확률 질량을 둔다.
- hard-negative rank: certain-safe 상태는 certainty만, guess 상태는 posterior만
  사용해 가장 높은 비권장 셀이 권장 셀보다 margin 아래에 오도록 한다.
- expected-risk regret: guess 상태의 posterior 행동 분포 기대 mine risk와 해당
  상태의 최소 solver risk 차이를 줄인다.
- guess-neutral: guess 상태의 certainty safe/mine margin을 0으로 수렴시켜
  posterior 2차 순위가 미세한 certainty 편차에 가려지지 않게 한다.
- posterior NLL/Brier: 확률 보정을 유지한다.
- class-weighted certainty CE: unknown 다수 클래스가 certain-safe/mine 학습을
  압도하지 않게 한다.
- 분리 mine BCE와 value MSE: 기존 보조 head 계약을 유지한다.

solver 출력은 이 손실의 teacher label 생성에만 사용한다. rollout action을 먼저
결정한 뒤 solver label을 붙이는 DAgger 순서를 테스트로 고정한다.

## 단계와 게이트

### R5-0 계약

- hidden mine layout 변경에 model input/output이 영향받지 않는다.
- inference 중 solver 호출은 실패한다.
- 9x9, 16x16, 16x30 padding 결과가 valid 영역에서 일치한다.
- preference 최대 영향은 설정 상한 이하다.
- v5 trunk/head 전이와 v6 checkpoint reload가 bit-identical이다.

### R5-1 ranking distillation

- CUDA AMP, BLAS/OpenMP thread 1개로 실행한다.
- Expert on-policy DAgger 상태와 세 난이도 rehearsal을 메모리에서만 구성한다.
- routine weight는 bootstrap.pt(최선)와 last.pt(최신)만 유지하고 round 지표는 작은 ranker.jsonl 하나에 기록한다.
- 고정 smoke가 baseline보다 개선되지 않으면 checkpoint를 덮어쓰지 않는다.
- canonical 진입 조건은 Beginner 85%, Intermediate 60%를 유지하면서 Expert
  validation이 R4 27.4%를 통계적으로 상회하고 35% 이상에 도달하는 것이다.

### R5-2 curriculum production

R5-1 진입 조건을 통과한 checkpoint만 curriculum bootstrap으로 사용한다.
최종 M6 게이트는 변경하지 않는다.

- Beginner rolling 500판 85% 이상, 3회 연속.
- Intermediate rolling 500판 60% 이상, 3회 연속.
- Expert rolling 500판 40% 이상, 3회 연속.
- NaN/발산 없음, checkpoint reload 재현.
- 최종 test suite는 checkpoint 선택 종료 후 한 번만 사용한다.

## 저장 및 자원 정책

- *.pt, *.onnx, .env, runtime state는 커밋하지 않는다.
- teacher sample은 메모리에서만 생성하고 대형 dataset 파일을 남기지 않는다.
- checkpoint는 bootstrap/last 역할별 최대 한 개만 유지한다.
- 로그는 JSONL 단일 스트림과 기존 회전 정책을 사용한다.
- GPU CUDA/AMP를 우선하고 CPU 수치 라이브러리 스레드는 1개로 제한한다.
## 실행 결과

### 기준선

- v5 기존 policy Expert smoke: 9/32 = 28.125%.
- v5 certainty-only Expert smoke: 12/32 = 37.5%.
- v5 certainty-only canonical validation: 55/200 = 27.5%.
- posterior-only Expert smoke: 5/32 = 15.625%.

### 방법 1: soft certainty + combined ranking

certainty probability margin을 1차 점수로 두고 모든 상태에서 combined policy CE,
hard-negative rank, expected-risk regret를 적용했다.

- 1,500 on-policy 상태 소규모 run: smoke 11/32 = 34.375%.
- 소규모 last canonical: 62/200 = 31.0%.
- 8,000 on-policy 상태, rehearsal 2,000개씩, 2 epoch:
  smoke 11/32 = 34.375%, canonical 61/200 = 30.5%.
- 학습 loss와 posterior Brier는 감소했지만 held-out top-1 mine rate는
  0.4%에서 0.5%, regret는 0.00054에서 0.00088로 악화됐다.
- 데이터 확대가 canonical 승률을 높이지 못해 실패로 판정했다.

### 방법 2: certainty/guess 분리 ranking

certain-safe 상태는 certainty rank만, guess 상태는 posterior rank/regret만
학습하고 guess certainty margin을 0으로 수렴시켰다.

- 동일 1,500상태 A/B smoke: 10/32 = 31.25%.
- held-out top-1 mine/risk/regret는 기준선 대비 개선되지 않았다.
- 이후 legal-mask 결함이 발견되어 이 방법의 수치는 최종 판정에서 무효화했다.

### 방법 3: strict class hierarchy

straight-through hard class로 safe > unknown > mine 순서를 강제하고 posterior는
같은 class 안에서만 정렬하도록 했다.

- 전이 직후 smoke: 5/32 = 15.625%.
- legal-mask 결함이 있던 최초 학습 수치는 무효화했다.
- legal-mask 수정 후 1,500상태 학습 smoke: 8/32 = 25.0%.
- held-out top-1 mine rate: 0.39%에서 0.78%로 악화.
- 유효 최종 checkpoint 92c222c5e03043c3aa82b3d77a42fb69.
- canonical validation: 44/200 = 22.0%, Wilson 95% CI 16.82-28.24%.
- R5-1 진입 조건 70/200 = 35%에 실패했다.

## STOP 판정

기존 R4 세 방법에 이어 유효한 R5 soft combined와 legal-mask 수정 strict
방법도 Expert 35% 진입 조건을 통과하지 못했다. M6 최종 40% rolling 500판
3회 연속 게이트는 변경하지 않으며 production curriculum과 M7은 시작하지 않는다. 실패 checkpoint는 배포하거나 M6 완료
산출물로 사용하지 않는다.

다음 시도는 단순 loss 가중치나 dataset 증량이 아니라 별도 승인이 필요한 새
대규모 아키텍처여야 한다. 후보는 learned search/planning, 명시적 belief-state
업데이트, 또는 solver와 구분되는 검증 가능한 신경 제약 실행기다.
### Legal-mask 결함 정정

최종 diff 검토에서 분리-loss의 posterior softmax가 legal mask를 적용하지 않아
revealed/padded 셀까지 정규화에 포함한 결함을 발견했다. 방법 2와 방법 3의
posterior CE/regret 결과는 이 결함 때문에 최종 판정 근거로 사용할 수 없다.
illegal posterior 값을 바꿔도 loss가 bit-identical한 회귀 테스트를 추가했으며,
strict ranker를 동일 조건에서 한 번 재실행한 뒤 STOP 여부를 다시 판정한다.
### Legal-mask 수정 후 최종 판정

illegal posterior가 loss에 영향을 주지 않는 테스트를 통과한 strict checkpoint는
smoke 8/32, canonical 44/200 = 22.0%였다. 따라서 잠정 STOP을 최종 STOP으로
확정한다.
